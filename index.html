一、为什么做

元宝助手二期路线图里写的"二次处理 = 可视化 + 自然语言对话交互"，是 AI 底层能力的下游。

上游能力（搜索 / 识别 / 抽取 / 处理）让 AI 生成出制品，但生成只是开始。真实链路是：


AI 生成制品  →  用户看 → 不完全满意 → 改  →  再不满意 → 再改  →  满意  →  使用 / 发布 / 留档

中间那一连串"改"，本质是对 AI 制品的二次编辑。当前现状：

  • 生成完直接 ❶ 重抽卡（让 AI 重做一遍，瞎猫碰死耗子）或 ❷ 跳出浏览器（导到 Word/PS/PPT 手改），两种都难受
  • 用户懂自己想要什么、却没编辑能力——不懂 PS、不懂 PPT 母版、不会写 CSS
  • AI 改稿和人工改稿互相隔离——AI 改完用户没法在结果上局部精修，用户改完 AI 看不到状态

二次编辑这一层是把这条断链补上的关键。做对了，AI 制品的有效产出率会从"勉强能用"涨到"可直接交付"。

浏览器是这件事的天然战场

  • AI 生成的制品里，HTML 占比最大（汇报方案、海报、报告、单页应用、多网页对比表、聊天气泡里嵌的图表）
  • HTML 是浏览器的母语，DOM 即编辑对象——hover/click 就能选中，无需安装任何编辑器
  • 过去没有"HTML 编辑器"赛道（Dreamweaver 死了 15 年），原因是普通人写不了代码；现在 AI 接住了代码门槛，浏览器接住了运行环境
  • "可视化点选 + 自然语言指令"双通道天然契合：用户拿不准时点元素 + 描述"换个颜色像 Notion 那种"，AI 改

二、二次编辑要服务的核心问题

不绕弯，先回答：用户拿到 AI 制品后，他到底想干什么？

把所有真实案例归到 6 种动作。每个动作 = 一个能力主战场。

动作用户原话频次
改文字"这段话改一下，太啰嗦了" / "这里加一句强调一下风险"极高
改样式"标题换个颜色" / "整体改 Notion 风" / "这块用卡片包一下"高
改结构"把这段移到前面" / "拆成两栏" / "加一个小节" / "删掉这个模块"高
改数据"把这个数字改成 230 万" / "图换成 6 月的" / "重新拉一下数据"中
改资产"图换一张" / "字体换思源黑" / "logo 换成新的"中
做协作"让汉博能在上面评论 / 改完看一下"中（场景集中在汇报）

跨动作的隐含需求：版本可回滚、改完能预览、能跨制品复用模板。

P0 一期清单（红色格子）

总共 13 个 P0 条目，归到 4 个能力域：

1. HTML 单页编辑器（5 个 P0）

  • 双击文字行内编辑 + 划词选中 AI 改写
  • 选元素弹工具栏，自然语言改样式（"换 Notion 风" "标题加粗"）
  • 元素级拖拽 / 增删 / 复制
  • 资产替换：图 / 字体 / 配色
  • 评论 + 版本回滚（已经做完，沉淀进 skill）

2. 文档编辑器（2 个 P0）

  • 行内编辑 + 划词 AI 改写（替换 / 续写 / 翻译 / 改风格）
  • 章节拖拽增删，目录联动

3. 表格编辑器（3 个 P0）

  • 单元格双击编辑
  • 增删行列、合并拆分
  • 字段绑数据源，一键重新拉

4. 图片 / 图表编辑器（3 个 P0）

  • 改图上文字（图层级编辑）
  • 换模板 / 换配色 / 换底图
  • 改图表标题轴、改数据

五、关键交互模式（底层共用）

不分制品，所有编辑都共用这 4 个交互范式。做对了，后面所有制品的编辑器都用同一套。

1. 可视化点选

  • hover 出半透明描边，告诉用户"这个元素可改"
  • click 选中，弹顶部工具栏（不是侧边栏，避免遮挡）
  • 工具栏只放 3-5 个高频动作 + 一个"AI 改"入口
  • ⌘/Ctrl 多选；拖拽框选

2. 自然语言指令通道

  • 选中元素后，输入框直接输自然语言："标题改成蓝色 + 字号大一号"
  • AI 把指令翻译成 DOM 操作（或样式 patch）
  • 可预览：改完先 hover preview，确认才落
  • 失败明确提示（不要"已执行"骗人）

3. 行内 / 直接操作

  • 文字双击进入编辑态（contentEditable）
  • 图片拖角调大小
  • 表格单元格点一下就编辑
  • 不弹模态框——所有操作就地完成

4. 版本与回滚

  • 每次编辑（人工或 AI）自动存快照
  • 历史最近 5 条 + 命名版本
  • 回滚 = 截断到目标版本（之前踩过坑：不要"再新增一个备份版本"）
  • 跨刷新可恢复（云端 latest.json）

六、底层共用规则

编辑触发时机

  • 用户切到"编辑态"（顶栏开关）→ 全页面可编辑
  • 用户 hover 元素 + 长按 → 局部编辑（不进入全局编辑态）
  • 链接被分享访问 → 默认只读，需密码进入编辑

性能约束

操作必须达到
点选元素50ms 内描边 + 工具栏出现
行内编辑落字0 延迟
AI 指令改样式3 秒内落，超过给进度条
AI 指令改内容（生成新文本）8 秒内落，流式输出
版本切换1 秒内重渲染

失败兜底

  • AI 改样式失败 → 工具栏退回，明确 toast"已撤回未生效"
  • AI 改内容失败 → 旧文本保留 + 失败标记，不要静默回滚
  • 网络断 → 离线编辑入 localStorage，恢复后批量同步

隐私和合规

内容处理
用户自己生成的制品只在用户本机和指定云端（gist/腾讯文档）存留
含个人信息（身份证 / 银行卡 / 私聊截图）编辑器内禁止生成可分享链接，必须先脱敏
AI 改稿调用的 prompt不留存原文，只留 hash
分享出去的链接默认带密码，密码不入 URL

七、二次编辑能力的需求明细

7.1 HTML 单页编辑器（一期主战场）

做到什么程度算合格

  • AI 生成 HTML 后，用户改的修改量 ≤ 20%（不用全重写）
  • 元素点选准确率 ≥ 95%（不会一选选到错的层级）
  • AI 改样式指令一次落对率 ≥ 80%
  • 改稿后导出可分享链接成功率 ≥ 95%（含版本、评论、密码保护）

关键决策

问题决策
选哪一级元素默认选最近的"语义块"（卡片 / 段 / 表行），用户可 ⌘+click 上探到父级
AI 改样式怎么落改 style 属性，不改 class（避免污染语义）
AI 改内容怎么落整段 replace；保留 data-* 属性；图片占位符 ↔ base64 来回换
撤回粒度一次 AI 调用 = 一个版本；连续多次手改合并成一版（防版本爆炸）
字体 / 配色资产从哪来内置 6 套（Notion / 商务 / 学术 / 小红书 / 大气 / 极简）+ 用户自定义
多人协作已有"评论 + 版本回滚 + 密码保护" skill（html-deploy-comments），复用

先做哪些 HTML 制品（按 PV 排序）

  1. 单页方案 / 汇报（已跑通，权益卡导流链路汇报）
  2. 多网页对比落地页（选车 / 选房 / 选商品对比表）
  3. 数据仪表盘（盯盘、自媒体数据后台）
  4. 海报 / 落地页（小红书图、商品主图升级版）

7.2 文档编辑器

做到什么程度算合格

  • 划词 → AI 改写命中率 ≥ 85%（改写后用户接受率）
  • 章节拖动操作每次成功率 ≥ 95%
  • AI 答案"P12 第 3 段"点击跳转回原文成功率 ≥ 98%（依赖文档抽取）
  • 笔记 / 批注 100% 不丢

关键决策

问题决策
编辑器引擎不自研，复用 ProseMirror / TipTap（成熟方案）
AI 改写颗粒度划词最小 = 短语，最大 = 段；超段需要"分段批改"模式
公式 / 代码块整块替换，不允许 AI 改公式的局部
文档+评论混编评论是独立层，不进文档正文

7.3 表格编辑器

做到什么程度算合格

  • 单元格编辑 / 行列增删每次成功率 ≥ 99%
  • "重新拉数据"成功率 ≥ 90%（依赖字段抽取）
  • 单元格 AI 指令理解率 ≥ 80%（"把这列改成万元单位""按 A 列升序"）

关键决策

问题决策
编辑器引擎复用 Univer / Luckysheet 或类 Notion 简化版（看交互需求）
数据源关联每列绑一个抽取规则；改了数据源自动重渲
公式一期不支持自定义公式，只支持 AI 翻译"求和这列"=>结果
跨表对比多表合并的逻辑放在抽取层，编辑器只负责显示和修改

7.4 图片 / 图表编辑器

做到什么程度算合格

  • 图层级编辑（文字 / 元素 / 背景分离）成功率 ≥ 85%
  • AI"换模板"指令一次到位率 ≥ 70%
  • 改完导出 PNG/SVG 准确率 100%

关键决策

问题决策
是否做 PS 级图层不做。只做"文字层 / 图片层 / 背景层"三层抽象
模板从哪来一期内置 30 套 + 用户上传
AI 生图复用哪条链路复用元宝矩阵的 AI 一键出图能力，本模块只做"生成后编辑"
图表用什么渲染ECharts（成熟、能内嵌交互）

7.5 协作能力（已沉淀）

  • 已完成 SCF 中转 + Gist 存储 + 密码保护 + 昵称强制（详见 html-deploy-comments skill v2.0）
  • 后续工作量：把同一套接入文档编辑器、表格编辑器、图片编辑器

九、怎么验证编辑器做得好

三层看

看什么衡量方式
编辑器本身好不好操作成功率、AI 指令命中率、操作耗时
下游交付好不好用户改完后导出 / 分享 / 留存的比例；改完后还要"二次修改"的比例
真实用户认不认主动唤起率、单次编辑深度（点了几下）、跨制品复用率（同一个模板用在几个制品上）

三类材料

类型用来做什么
黄金样本集：人工标注的 100 个高频改稿任务发版前必跑，覆盖 6 大动作 × 5 大制品
真实日志采样：每月从用户编辑历史里随机抽 200 条看通用方法在没见过的制品上够不够
历史回归集：踩过的坑发版前必跑，通过率不低于上一版

十七、不做什么的决断（主动剪枝）

参考文档真正的灵魂在 "不做什么"。第一版我只做了"我能做到什么"，没显式说"我故意不做什么"。这章列出 9 条主动剪枝。

#不做为什么不做替代方案 / 边界
1不做 PS 级图层编辑器PS 用户不会迁移过来；浏览器做这件事性价比极低只做"文字层 / 图片层 / 背景层"三层抽象；用户要更深图层就跳 PS
2不做 PPT 整套编辑器PPT 母版 / 动画 / 切换页 是 12 年深的工具链，复制不动一期只允许 PPT 行内文字改；其他动作引导用户导出到 PowerPoint
3不做视频剪辑视频剪辑赛道在专业工具里，浏览器没竞争力只做"视频笔记的字幕和章节文本编辑"，不碰画面
4不做实时多人协同光标Figma / Google Docs 的 OT/CRDT 是 5 年的工程量用"评论 + 版本"做异步协作；多人想同时改 = 排队
5不做自定义公式 / 函数表格自定义公式是 Excel 30 年沉淀，做不过一期只支持 AI 翻译"求和这列""按 A 升序"等自然语言到结果
6不做模板市场一期没有用户量做不起来，二期再说用户自定义模板只在自己账号下沉淀，不公开流通
7不做大量 AI 模型自训一期没数据飞轮复用 DeepSeek / 元宝矩阵的现成模型，攒数据后再考虑 fine-tune
8不做编辑器主题市场化（大量预设）主题预设过多反而让用户不知道选哪个内置 6 套（Notion / 商务 / 学术 / 小红书 / 大气 / 极简）封顶
9不做"无 AI 也能用"的纯手动编辑器离了 AI 就退化成 Notion 的低配版本，没壁垒编辑器和 AI 强耦合：所有操作都可以走 AI 指令，也可以手动；但默认引导是"AI 优先"

这章的反向价值

写"不做"比写"做"难——做的是产品本能，不做的是产品判断。每一条"不做"都意味着拒绝了一个看似合理的功能扩张诉求，是规划评审时给 leader 的最强信号："我懂边界。"

十九、用户行为驱动的验收口径（重写第九章·三层看里的最关键一层）

第一版第九章第一层"编辑器本身好不好"用的是模型能力指标（命中率 / 准确率），第二、三层偏笼统。这章按参考文档"用户行为是最终裁判"的范式，把每一类指标改成可观测的用户行为信号。

19.1 第一层：编辑器自己好不好（操作可用性）

指标怎么算合格线数据从哪来
元素点选准确率"用户点了 X，但实际编辑了 Y" / 总点选次数≤ 5% 错选编辑日志埋点（点选目标 ID 和最终被改 ID 比对）
AI 指令理解一次过率用户输入指令 → AI 返回 → 用户没立即撤销≥ 80%"执行 → 撤销" 时间窗（10 秒内）埋点

崩溃率编辑过程中页面挂掉 / 数据丢< 0.1%Sentry 类异常监控

19.2 第二层：下游交付好不好（用户行为）

这是参考文档的核心范式。指标的裁判不是算法测试集，是真实用户的下一步动作。

指标怎么算合格线数据从哪来
改完后导出 / 分享率编辑会话结束后，多少比例触发了导出 / 复制链接 / 分享≥ 40%编辑会话 + 导出/分享事件关联
改完后回头再改率（坏信号）同一制品在 24h 内被同一用户多次进入编辑≤ 25%userId + 制品 ID 的会话聚合
AI 改稿后用户局部精修率（好信号）AI 改完后，用户对结果做局部修订 = 信任 AI + 还能继续打磨30% ~ 60% 健康区编辑事件序列分析
AI 改稿后整段撤销率（坏信号）AI 改完用户直接 ctrl+Z 整段回滚≤ 15%撤销事件
二次编辑链路完成率进入编辑 → 改至少一处 → 退出时未丢弃≥ 70%进入 / 编辑动作 / 退出三事件漏斗

19.3 第三层：真实用户认不认（习惯养成）

指标怎么算合格线数据从哪来
主动唤起率AI 生成完后，用户主动点击进入编辑器 / 总生成次数≥ 50%生成事件 + 编辑入口点击
单次编辑深度一次编辑会话内的操作次数（点选 / AI 指令 / 直接操作）中位数 ≥ 5 次操作埋点聚合
跨制品复用率同一用户在同一周内对 ≥ 2 类制品都用了编辑器≥ 25%userId + 制品类型聚合
30 日留存第一次用编辑器的用户，30 天内再用≥ 40%userId + 日期 cohort

19.4 失败警告（参考文档最强的一招）

如果第二层指标长期低于合格线，意味着：

  • 改完后导出率 < 20% → 用户改了但不交付：要么改得不满意，要么改完没下一步可走 → 整个二次编辑模块的存在意义被质疑
  • 整段撤销率 > 30% → AI 在帮倒忙：用户宁愿不要 AI 也不要被乱改 → AI 指令通道要降级或重做
  • 主动唤起率 < 20% → 入口太深 / 生成完用户根本想不到能改 → 生成完成提示要重做

这三条任意一条触发警告 30 天，必须暂停新功能扩张，专项整改。
